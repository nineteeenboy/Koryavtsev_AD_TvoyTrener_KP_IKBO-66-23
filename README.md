# Твой тренер

## Настройка
- JDK 21, Android SDK 37 (compile), minSdk 24, targetSdk 34; Gradle Wrapper уже в проекте.
- Сервер: `DATABASE_URL=jdbc:postgresql://<neon-host>/<database>?sslmode=require`, `DATABASE_USER`, `DATABASE_PASSWORD`, `FIREBASE_SERVICE_ACCOUNT_PATH` (абсолютный путь к JSON сервисного аккаунта); опционально `PORT=8080`.
- `JWT_SECRET` не нужен: Firebase подписывает ID Token, Admin SDK проверяет его подпись, срок действия и отзыв; локальные JWT не выпускаются.
- Замените плейсхолдер `app/google-services.json` конфигурацией Firebase для `com.example.trainer`, включите Authentication → Email/Password; сервисный аккаунт должен принадлежать тому же Firebase-проекту.
- Адрес API: `API_BASE_URL=https://your-server/` в env или `local.properties`; по умолчанию эмулятор использует `http://10.0.2.2:8080/`. На физическом устройстве используйте HTTPS либо `adb reverse tcp:8080 tcp:8080` и `API_BASE_URL=http://localhost:8080/`.

## Запуск
```shell
./gradlew :server:seed
./gradlew :server:run
./gradlew :app:assembleDebug
./gradlew :app:installDebug
```
Windows: `gradlew.bat` вместо `./gradlew`; либо откройте этот проект в Android Studio и запустите модуль app.

Для локального запуска сервера в PowerShell из папки проекта: `powershell -ExecutionPolicy Bypass -File .\Start-Server.ps1`. Скрипт читает настройки сервера из env или исключённого из Git `local.properties`. Сервер должен работать во время входа и использования приложения; запуск только модуля app его не запускает.

Таблицы создаются через `SchemaUtils.create` при старте сервера; seed идемпотентно создаёт 17 профилей: 12 с DDX Fitness и 5 из предоставленных материалов. Старые карточки со случайными аватарами заменяются на DDX с сохранением ID и связанных записей.

Каталог DDX: снимок публичных профилей https://www.ddxfitness.ru/coaches/ от 24.10.2026. Имена, стаж, фотографии и направления взяты из официальных карточек; описания сокращены, ссылка на источник есть в каждом профиле. Фото включены в ресурсы сервера `/media/ddx/`. Записи хранятся в собственной базе приложения и не передаются в систему DDX.

Регистрация/логин выполняются Firebase SDK на клиенте; `POST /auth/register` и `POST /auth/login` получают Bearer ID Token и синхронизируют SQL-профиль. Сервер не принимает пароли.
Первый экран открыт гостям. Фото залов встроены в APK; пять профилей из предоставленных материалов добавляются при старте сервера, фото доступны по `/media/trainers/`. Если имя отсутствует, отображается профессиональная роль. Старые записи и отзывы сохраняются.
Занятия по часу, 09:00–21:00 МСК, запись на ближайшие 90 дней. Отзыв доступен после окончания неотменённой тренировки; один отзыв на тренера.

## Заявки, администратор и тренеры
- Укажите `ADMIN_EMAILS` (адреса через запятую) в окружении сервера или `local.properties`. `Start-Server.ps1` загружает эту настройку. Назначение роли выполняется на сервере по email из проверенного Firebase ID Token; клиент не может назначать роли.
- Войдите под настроенным аккаунтом администратора и откройте «Профиль → Заявки тренеров». Доступны очередь и история решений. При отказе обязательна причина.
- «Стать тренером» сохраняет заявку в PostgreSQL. Статус и комментарий администратора доступны в «Профиль → Моя заявка тренера». После отказа заявку можно исправить и отправить повторно.
- Подтверждение атомарно создаёт карточку в каталоге, связывает её с аккаунтом и переводит заявку в `APPROVED`. Профиль получает роль `TRAINER`; в профиле появляется «Дневник тренировок».
- В дневнике отображаются собственные записи тренера, имя клиента, дата, статус и стоимость. К записи можно добавить или изменить заметку до 20 000 символов; заметки сохраняются на сервере и не передаются клиентам или другим тренерам. Отмена записи сохраняет заметку в истории.
- Новые таблицы `trainer_applications`, `trainer_accounts`, `training_notes` создаются при запуске без изменения существующих пользователей, записей и отзывов. Начальный каталог содержит 17 профилей и пополняется после одобрения заявок.

Для Compose-тестов нужен запущенный эмулятор или устройство; Firebase/Neon не нужны. Ktor-тесты используют H2 и MockK только для Firebase-границы.
